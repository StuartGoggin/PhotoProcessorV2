# Subject mask research for PhotoGoGo video finishing

Research date: 10 October 2026. This is a source review and proposed evaluation plan, not an implemented feature or a measured hardware result. No dependencies, models or media were downloaded; no application code changed.

## Recommendation and blue-team verdict

**Upside:** A correctable horse-and-rider mask can support restrained subject colour/light adjustment and sharpening while protecting the existing defocused background. Interactive video segmentation already offers correction on later frames, which is important when the horse approaches the camera, crosses obstacles, or changes pose.

**Downside:** Whole-object segmentation accuracy does not establish acceptable alpha edges for mane, tail, reins and motion-blurred legs. Memory-efficient model architecture does not establish bounded application memory. Intel Arc development results cannot establish RTX 2060 performance. Broad semantic auto-selection adds a detection/pairing problem to an already difficult edge-quality problem.

**Verdict: modify, then validate.** Use SAM 2.1 tiny/small as the first quality baseline, with user confirmation of the horse/rider group and later correction points. Compare Cutie as the frame-streaming alternative for long clips. Evaluate these on actual stabilized Canon R6 Mark II 4K50 footage before choosing a product dependency. Consider SAM 3.1 as a subsequent automatic proposal generator, subject to its custom licence, gated model access and hardware tests. It is not necessary to make it the first shipped backend.

**Alternatives:** Use conservative tracked subject-core masks initially; add optional image-matting refinement only if it improves a temporally assessed result. A simple correction workflow with restrained effects may outperform an elaborate fully automatic chain in visible reliability. Keep difficult intervals unprocessed until corrected.

**Next step:** A separately authorized, bounded evaluation of SAM 2.1 tiny versus small, plus Cutie if its checkpoint terms are accepted, on short representative clips and a long-memory stress case. The evaluation should report quality, correction cost, memory and complete decode-to-mask elapsed time. No throughput estimate is made here.

## Footage and product assumptions

The target is the user's original 4K50 Canon R6 Mark II footage, 400 mm f/2.8, tripod horse tracking, with horse and rider selected together. Preserve the buttery background bokeh. Include shots where the horse fills most of the frame; an area near 100% is not automatically an error. Effects run after stabilization in the stabilized image coordinate system. Masks, prompts and frame timestamps must refer to exactly that image sequence. These are user/task constraints, not model guarantees.

Proposed behaviour: show the selected group, confidence/uncertainty overlay, correction controls and invalid intervals. Store separate horse/rider identities when useful, while exposing one finishing group. Keep the mask independent of effect strengths so adjusting colour does not rerun segmentation. Use a conservative inner mask for sharpening and a more carefully refined boundary for colour; uncertain thin edges should receive less effect. These are design recommendations.

## Prompted selection versus automatic detection

SAM 2 automatic mask generation is an image-region proposal facility, not a semantic horse/rider detector. Its `stability_score` measures robustness to the mask binarization threshold, not temporal stability. SAM 3's concept facility does add text detection. A prompt such as `horse` can produce multiple matching instances; matching a particular rider to a particular horse and grouping their masks is still application logic. A phrase such as `horse and rider` is not a documented guarantee of one combined mask with reins and saddle. Proposed UI: confirm the suggested pair once, retain identities, and allow point/brush correction. [SAM 2 automatic mask API](https://github.com/facebookresearch/sam2/blob/main/sam2/automatic_mask_generator.py), [SAM 3 concept API](https://github.com/facebookresearch/sam3)

An alternative is keyframe-only detection followed by SAM 2/Cutie propagation. Grounding DINO officially accepts image/text inputs and returns boxes with token similarities; its repo links Grounded SAM 2 integration and uses Apache 2.0 for repo code. This supports proposing horse/person boxes without running a large concept model on every frame. It still adds detection/text-backbone checkpoints and compiled operator dependencies, whose offline closure and exact weight terms need review. It is a deferred alternative, not an accepted extra dependency in the first experiment. [Grounding DINO official repository](https://github.com/IDEA-Research/GroundingDINO)

## Segmentation quality and confidence

The SAM 2 paper explicitly reports difficulty with thin/fine fast-moving details, nearby similar objects, shot changes, crowded scenes, long occlusion and extended videos. Later correction prompts can recover many tracking errors. Those limitations directly intersect with reins, mane, legs and horse/rider occlusions; generic benchmark accuracy is insufficient for this footage. [SAM 2 paper, Appendix C](https://arxiv.org/html/2408.00714v2)

SAM 2's image predictor returns predicted mask quality and unthresholded logits; the model also has an object visibility head. Cutie's streaming core returns normalized foreground/background probabilities. These are useful signals, but this review found no horse-footage calibrated probability that a finishing mask is safe. Segmentation probability is also not physical alpha/transparency. [SAM 2 image API](https://github.com/facebookresearch/sam2/blob/main/sam2/sam2_image_predictor.py), [SAM 2.1 configuration](https://github.com/facebookresearch/sam2/blob/main/sam2/configs/sam2.1/sam2.1_hiera_s.yaml), [Cutie inference core](https://github.com/hkchengrex/Cutie/blob/main/cutie/inference/inference_core.py)

Proposed confidence assessment combines several signals: model quality/visibility, disagreement of forward and backward propagation on bounded intervals, motion-compensated disagreement near the boundary, plausibility of movement/shape change, proximity to a confirmed correction, and shot/occlusion events. Calibrate thresholds on held-out footage. Do not call a score such as 0.9 a 90% safety guarantee. Do not reject large masks or quickly approaching horses merely because their size changes.

Proposed abstention: missing identity, low-quality boundary, disagreement after occlusion or an unresolved scene change produces an explicit invalid interval. Do not propagate a stale matte across that interval. Either require a correction or apply zero finishing effect there; make the chosen behaviour visible. Smooth effect transitions only within reliable intervals, because fading cannot repair a wrong identity.

## Bounded memory is an implementation requirement

The stock SAM 2 predictor keeps images, prompts and per-object output dictionaries in an inference state. CPU offload moves those allocations; it does not by itself cap them. The frame loader creates tensors for all JPEG frames, while its MP4 path accumulates and stacks all decoded frames. The asynchronous JPEG loader also caches frames, so asynchronous loading alone is not a memory bound. [SAM 2 predictor source](https://github.com/facebookresearch/sam2/blob/main/sam2/sam2_video_predictor.py), [SAM 2 frame loader source](https://github.com/facebookresearch/sam2/blob/main/sam2/utils/misc.py)

Derived illustration, not a benchmark: at the supplied configuration's 1024-square float32 RGB input, each normalized frame occupies 12 MiB. One minute at 50 fps is 3,000 frames, approximately 35.2 GiB just for that image tensor, before model/state/output storage. The config uses seven mask-memory slots, but retained application output dictionaries still require a separate bound. [SAM 2.1 small config](https://github.com/facebookresearch/sam2/blob/main/sam2/configs/sam2.1/sam2.1_hiera_s.yaml)

Proposed SAM 2 baseline: process bounded intervals with CPU frame offload, explicit output eviction and persisted masks. Start with small windows and overlap anchored by confirmed masks. Validate chunk seams and occlusion recovery: resetting state can discard useful history. Do not claim a stock full-clip `init_state` call is production streaming, and do not prune internal state blindly without equivalence tests.

Cutie provides a more explicit frame-at-a-time `InferenceCore.step`. Its config limits working memory and, when enabled, long-term tokens: default non-long-term memory is five frames; long-term settings include 10/5 max/min frames, 128 prototypes and 10,000 tokens. The memory manager compresses or evicts old nonpermanent features. Permanent correction anchors must also be capped by the application, and bounded neural state does not excuse an unbounded decoded-frame or output queue. [Cutie scripting example](https://github.com/hkchengrex/Cutie/blob/main/scripting_demo.py), [Cutie memory config](https://github.com/hkchengrex/Cutie/blob/main/cutie/config/eval_config.yaml), [Cutie memory manager](https://github.com/hkchengrex/Cutie/blob/main/cutie/inference/memory_manager.py)

Proposed disk-backed state: immutable model/checkpoint identifier; source fingerprint; stabilized sequence fingerprint; frame timestamp; group/object IDs; prompt/correction history; masks; validity intervals; and inference settings. Corrections invalidate only affected intervals, with the dependent propagation range made explicit. Enforce bounded decode queues, mask queues, neural state and permanent anchors. Include cancellation, disk-full handling and resumable checkpoints.

## Windows, CUDA, Intel Arc and ONNX boundaries

SAM 2 documents Linux requirements and strongly recommends Ubuntu under WSL on Windows. Its custom CUDA connected-component extension can be disabled with `SAM2_BUILD_CUDA=0`; official instructions say both image/video inference remain usable, with hole/sprinkle cleanup omitted. This supports a native Windows feasibility experiment, not a claim of upstream native Windows certification. Do not silently fill the gaps between legs or reins during mask cleanup. [SAM 2 installation notes](https://github.com/facebookresearch/sam2/blob/main/INSTALL.md), [SAM 2 setup](https://github.com/facebookresearch/sam2/blob/main/setup.py)

Cutie documents Ubuntu-only testing and CUDA examples. Its package metadata includes a broad GUI/training/tool dependency set, including PySide6, gradio, compiled packages and a direct Git dependency. A packaged PhotoGoGo worker should therefore evaluate a narrow inference dependency closure, rather than inherit the entire interactive research demo. Native Windows support needs a real import/inference test. [Cutie package metadata](https://github.com/hkchengrex/Cutie/blob/main/pyproject.toml)

SAM 3's documented baseline requires Python 3.12+, PyTorch 2.7+ and CUDA 12.6+; its current example installs PyTorch 2.10 CUDA 12.8. Its optional accelerated kernels are not a universal RTX 2060 requirement. A model fitting in VRAM is not equivalent to the whole pipeline fitting with inference activations, video decoding and encoding. The approximately 1.58 GiB implied by 848M FP16 weights is only arithmetic, not measured peak memory. [SAM 3 README](https://github.com/facebookresearch/sam3)

Do not copy an A100/H100 BF16/compile benchmark configuration blindly to Turing. Select FP16/FP32 through runtime capability checks and measure output parity. SAM 2 published speeds were measured on an A100; SAM 3.1's highlighted multiplex speedup is for 128 objects on an H100, a very different workload from one horse/rider group. [SAM 2 benchmark disclosure](https://github.com/facebookresearch/sam2#model-description), [SAM 3.1 efficiency disclosure](https://github.com/facebookresearch/sam3/blob/main/RELEASE_SAM3p1.md), [PyTorch BF16 capability API](https://docs.pytorch.org/docs/main/generated/torch.cuda.is_bf16_supported.html)

Microsoft owns an ONNX Runtime SAM 2 exporter. The inspected exporter only lists image encoder, image decoder, prompt encoder and mask decoder; its documented checkpoint names and environment refer to original SAM 2, not a complete SAM 2.1 video tracker. It is useful evidence for static correction/keyframe inference, not proof of exported memory attention, propagation or interactive video correction on DirectML. [Microsoft SAM 2 export README](https://github.com/microsoft/onnxruntime/blob/main/onnxruntime/python/tools/transformers/models/sam2/README.md), [export component list](https://github.com/microsoft/onnxruntime/blob/main/onnxruntime/python/tools/transformers/models/sam2/convert_to_onnx.py)

ONNX Runtime's DirectML documentation says it is in sustained engineering with new Windows development moving to WinML. It supports opset 20 with exclusions, requires sequential execution and disabled memory patterns, and prohibits concurrent `Run` calls on the same session. Static shapes generally improve execution. These constraints matter for an optional future portable worker; hardware support does not establish support for a particular exported video model. [DirectML execution provider](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)

PyTorch has an official XPU path supporting Intel Arc on Windows 11, including inference. However, these repositories' CUDA-specific paths/extensions still need adaptation and validation. Arc can support UI, contracts, CPU reference tests and potentially an XPU experiment; it cannot substitute for a render-PC RTX 2060 CUDA acceptance run. [PyTorch Intel GPU guide](https://docs.pytorch.org/docs/2.10/notes/get_start_xpu.html)

## Matting/refinement and licence boundaries

Cutie and XMem repo licences are MIT. Their reviewed README/release sources did not explicitly distinguish pretrained checkpoint rights from code rights, so this report does not present a separately verified checkpoint redistribution grant. That is a provenance gap to close, not a claim that the authors forbid checkpoint use. [Cutie licence](https://github.com/hkchengrex/Cutie/blob/main/LICENSE), [XMem licence](https://github.com/hkchengrex/XMem/blob/main/LICENSE)

ViTMatte accepts an image and trimap and outputs alpha. Official repo code is MIT. The HUST model hub's small Composition-1k checkpoint is labelled Apache 2.0 and has a safetensors variant; its model card explains that Hugging Face wrote the card. Treat the model artefact's terms separately from the repo code terms. A narrow unknown edge band derived from a tracked mask is a plausible experiment, but erosion can delete fine reins and confident trimap errors can prevent their recovery. It offers no inherent video temporal guarantee. [ViTMatte repository](https://github.com/hustvl/ViTMatte), [input contract](https://huggingface.co/docs/transformers/en/model_doc/vitmatte), [checkpoint card](https://huggingface.co/hustvl/vitmatte-small-composition-1k), [checkpoint files](https://huggingface.co/hustvl/vitmatte-small-composition-1k/tree/main)

RVM is expressly human matting and publishes ONNX and other formats; its repository code is GPL 3.0. Its reported RTX 2060 **Super** result is for a different model/task/device and cannot predict horse segmentation performance on the user's RTX 2060. MatAnyone and MatAnyone 2 are also expressly human frameworks. Both S-Lab licence files permit noncommercial use and direct commercial-use requests to the authors. Their titles are not evidence of any-object horse support. [RVM official repository](https://github.com/PeterL1n/RobustVideoMatting), [MatAnyone official repository](https://github.com/pq-yang/MatAnyone), [MatAnyone 2 official repository](https://github.com/pq-yang/MatAnyone2), [MatAnyone licence](https://github.com/pq-yang/MatAnyone/blob/main/LICENSE), [MatAnyone 2 licence](https://github.com/pq-yang/MatAnyone2/blob/main/LICENSE.txt)

MatAnyone 2's learned quality evaluator is also listed as a pending release in its repo; do not promise a ready-made calibrated quality scorer. ## Sparse keyframes and flow assistance

Proposed primary baseline tracks every frame at a controlled internal resolution, with sparse user correction keyframes. A second experiment may propagate masks using optical flow between more expensive segmentation keyframes. Treat flow as correspondence support, not semantic re-identification: it cannot reconstruct hidden legs, newly visible mane, frame exits or identity after occlusion. Linear mask interpolation is especially weak during leg crossings and pose changes. Adapt keyframe spacing to motion/uncertainty, and re-prompt after shot changes. No safe universal keyframe interval or measured cost saving is established here.

At 4K, downsampling may remove the very reins/detail under evaluation. Cropping can help smaller subjects, but near-frame-filling horses provide little crop saving. Inspect high-resolution boundary patches separately; do not promise that upsampling a coarse mask restores lost detail. Full-resolution colour compositing and sharpening should remain streaming even when inference uses proxies.

## Proposed quality and operational gates

All thresholds below are proposed acceptance criteria, not observed results. Establish them before comparing models and adjust only through a recorded decision, not to excuse a failed candidate.

1. **Representative footage:** include ordinary tracking, close approach/frame fill, fast legs, tail/mane wind, dark reins, horse/rider overlap, obstacle/fence occlusion, entering/leaving frame, light changes and background people/horses. Use stabilized frames. Include clean shots and deliberately difficult cases; reserve held-out clips.
2. **Identity:** zero silent switches to another horse/person. Background gaps between legs and reins remain background. A switch or lost group must be corrected or explicitly invalidated, including after a long occlusion.
3. **Edges:** review at 100%/200% pixel view and at 50 fps. Check mane, tail, helmet, clothing, saddle, reins and all legs. No persistent visible halo, hard cutout, stair steps or clipped anatomy in accepted intervals. Inspect boundary overlays and a deliberately exaggerated temporary grade to expose spills.
4. **Temporal stability:** review normal-speed and slow-motion crops. Measure motion-compensated boundary/alpha change on visible regions, excluding genuine disocclusion. Compare with a manually reviewed reference and model alternatives. No numeric universal flicker threshold is invented; a production threshold must be chosen on the actual footage. Test interval overlaps and resumed rendering separately.
5. **Bokeh preservation:** before lossy encoding, pixels outside the permitted mask/effect support must equal the stabilized input. Compare the output to the stabilization-only baseline using identical encoding to distinguish encoder changes from finishing spills. The background should not receive added sharpness, texture or colour pumping.
6. **Confidence/abstention:** all deliberately introduced wrong-identity/absent-subject failures in the test set must be signalled or require correction. Test confidently wrong predictions. Calibrate score thresholds on held-out cases and record miss rate, false warnings and effect-disable durations.
7. **Correction cost:** a correction on a later frame must repair the intended range without changing approved earlier intervals unexpectedly. Store prompts and undo history. Proposed usability target: repair an isolated failure with a small number of clicks; report actual clicks/minute and time rather than assume it.
8. **Memory bound:** RTX 2060 6 GB run must remain within an explicit budget including concurrent decoder/encoder work, with at least 1 GiB headroom as an initial proposal. Demonstrate approximately flat RAM/VRAM after warmup on increasing clip length and an uninterrupted 10-minute case. Measure actual peak, not model weight size. An OOM rejects the profile rather than silently lowering quality.
9. **Throughput:** measure first mask latency, warmup, masks/sec, complete processing time, peak RAM/VRAM and disk footprint on the RTX 2060. Separate decode, inference, refinement and output costs. Arc results are labelled Arc. An acceptable offline time budget still needs agreement; 50 fps source rate is not an inference-speed promise.
10. **Offline and resilience:** once provisioned, inference works with network disabled and without token/auth refresh. Missing/corrupt model, unsupported GPU, non-finite mask, cancellation, disk-full and interrupted process yield a clear result with original media intact. Resume from a verified checkpoint and invalidate caches on changed stabilization/model/prompt state.
11. **Package integrity:** freeze source and model revisions, actual artefact SHA-256, dependency lock, licence notices and SBOM. Avoid untrusted checkpoint loading and auto-fetch helpers. Verify installed worker import and one real mask run on a clean native Windows target. Native/WSL, CUDA/XPU/ONNX and different precision profiles each need separate acceptance evidence.

The hard stop is a failed gate, not a request to broaden the experiment indefinitely: after two failed bounded attempts at the same essential quality or memory criterion, record the failure and choose a simpler mask/effect profile or defer the feature. The recommended experiment is not an approval to install, download, benchmark or implement anything in this research turn.

## Follow-up: finite-window Windows adapter and detector provenance

This section makes the proposed adapter concrete. It supersedes the earlier historical Torch 2.5.1 runtime illustration as an executable candidate. It remains a design/source review, with no installed environment, downloaded checkpoint, footage run or app change.

### Current checkpoint-loader security gate

The upstream SAM 2 builder loads its `.pt` checkpoint using `torch.load(..., weights_only=True)`. That flag is not a universal security guarantee: PyTorch's April 2025 advisory affects versions through 2.5.1, and its January 2026 advisory affects versions through 2.9.1, with the latter patched from 2.10.0. Therefore reject the historical 2.5.1 pair for a newly packaged checkpoint-loading worker. [SAM 2 builder at reviewed revision](https://github.com/facebookresearch/sam2/blob/2b90b9f5ceec907a1c18123530e92e794ad901a4/sam2/build_sam.py), [2025 official advisory](https://github.com/pytorch/pytorch/security/advisories/GHSA-53q9-r3pm-6pq6), [2026 official advisory](https://github.com/pytorch/pytorch/security/advisories/GHSA-63cw-57p8-fm3p)

An official matched Windows candidate is Torch 2.10.0 / TorchVision 0.25.0 with CUDA 12.6 or 12.8 wheels. This is a starting point for security/dependency and RTX 2060 compatibility validation, not a declaration that it is the latest, fully audited or measured pair. Torchaudio is unnecessary for this mask worker. Refresh advisories before freezing the eventual manifest. Restrict model paths to a manifest allowlist, verify acquired SHA-256, disallow arbitrary model code and checkpoint uploads, and use a private worker/cache directory. [Official version pairs](https://pytorch.org/get-started/previous-versions/)

### Proposed adapter contract

Use a separate local Python worker with one loaded tiny/small model and a narrow job contract: stabilized sequence fingerprint, fixed image dimensions, global frame/timestamp mapping, bounded window range, group/object IDs, correction anchors, model/config hashes and inference profile. Return frame-tagged masks, validity/reason codes and timings. Do not send original media to a service. Keep process launch arguments structured, paths validated and logs free of private frame pixels.

1. **Load once, use a finite input.** Build from the local checkpoint/config, initially eager (`vos_optimized=False`) with the CUDA extension disabled. Explicitly record postprocessing settings; an initial `apply_postprocessing=False` profile avoids default hole filling and must be compared for quality. On RTX 2060 evaluate FP16 against FP32; retain CPU reference tests on the Arc development machine. An XPU profile is separate. No native Windows compiler or `torch.compile` is required by this initial proposed profile.
2. **Materialize only a bounded stabilized window.** Stock JPEG input is practical for a first adapter; keep integer filenames, fixed dimensions and an explicit local-to-global index table. Do not extract the whole clip. Test JPEG proxy compression for fine reins/mane; source-resolution compositing still reads the stabilized original-quality stream. A lossless arbitrary in-memory provider would require a separately reviewed adapter, not a claim about the stock JPEG loader.
3. **Start conservatively.** An illustrative window is 100 frames including 16 frames of overlap (2 seconds total at 50 fps), not a proved safe profile. Windows `[0,100)`, `[84,184)` have disjoint owned output ranges `[0,84)`, `[84,168)`; the final window owns its remaining tail. Lookahead/overlap outputs support seam checks, not duplicate output frames. The 1024-square float32 input alone is about 1.17 GiB for 100 frames. Reduce the window if the complete CPU/GPU budget fails; measure model state, original-resolution transient masks and decode/encode allocations separately.
4. **Fresh state each window.** Call `init_state` only on that window, with CPU frame/state offload and initially synchronous loading. Persist each yielded output immediately through a bounded queue, then discard the entire inference state after the window. Retain the model, not accumulated states. Do not implement undocumented dictionary pruning for the first baseline. The memory ceiling is the configured window and queues, with no hidden full-clip decode list.
5. **Track identities separately, finish as one group.** Reuse application IDs such as `horse-1` and `rider-1`, mapping them consistently to predictor IDs. Union their finishing masks without forcing non-overlap between two members of the same group. A reused integer ID is bookkeeping, not re-identification evidence.

Relevant public API boundaries: `max_frame_num_to_track` bounds propagation, not initial frame loading; its range includes the start frame, so test frame counts explicitly. `reset_state` clears tracking/prompts/IDs but not loaded images. Pixel prompts are converted from video dimensions. `add_new_mask` consumes a 2-D seed and may resize/threshold it; keep binary identity seeds separate from refinement alpha. These facts are directly visible in the [reviewed predictor](https://github.com/facebookresearch/sam2/blob/2b90b9f5ceec907a1c18123530e92e794ad901a4/sam2/sam2_video_predictor.py) and [frame loader](https://github.com/facebookresearch/sam2/blob/2b90b9f5ceec907a1c18123530e92e794ad901a4/sam2/utils/misc.py).

### Boundary handoff, correction and abstention

The following is application policy, not an upstream guarantee of continuous identity or calibrated confidence.

- Choose a visible accepted mask in the shared overlap, preferably a confirmed correction anchor when available; never blindly use the last frame. Seed the new state with separate horse/rider masks and propagate forward. If the anchor is after the owned range's first frame, use reverse propagation to cover the preceding owned frames. Keep seed and output dimensions identical to the stabilized window's coordinate system.
- Compare newly predicted masks with prior overlap predictions on non-seed visible frames. Check identity, gaps between legs, thin details, boundary movement and motion-compensated disagreement. High overlap IoU can hide lost reins; agreement between two wrong masks can hide an identity switch. Do not average conflicting masks to hide the seam. Threshold stability and detection scores must not be renamed temporal confidence.
- If an object is absent/occluded throughout the available overlap, the new state has no demonstrated appearance history for it. Permit a strictly bounded lookback to an earlier accepted visible anchor, or mark the identity unresolved and require confirmed reacquisition. A detector finding another horse/person after occlusion is a suggestion, not proof it is the original pair. Never inject an empty mask as if it re-established a hidden object's identity. Conservative initial policy: invalidate the finishing group when either required member has unresolved identity; distinguish verified absence from loss.
- Persist manual anchors/prompts, accepted masks and dependency lineage on disk. Mark automatic carry anchors as generated, not manual ground truth. A correction invalidates dependent generated anchors/results until the next independently approved boundary. Rebuild only affected bounded windows, present the changed interval, and commit accepted results transactionally. Earlier approved ranges remain immutable unless explicitly included in the correction scope. If a window contains too many anchors for its state budget, split it; do not silently discard user corrections.
- For forward/backward disagreement testing, run independent directional passes sequentially from their approved anchors, with disk-backed comparison, rather than simultaneously retaining two full states or presenting reused state as an independent check. Store ordinary masks/anchors/settings as the resumable contract; this review did not establish a supported, version-stable neural-state serialization contract.
- Log chunk ranges, anchor lineage, rejected seams, identity/visibility reason codes, inference time, RAM peak, CUDA allocated/reserved peak and queue high-water marks. Test global frame coverage, cancellation and resume at every seam. GPU reserved memory need not fall to zero; it must plateau across increasing clip length. Apply zero subject finishing in invalid intervals and surface the reason in preview.

This is bounded offline processing, not a claim of uninterrupted recurrent streaming. Its main quality risk is discarded appearance/context at each reset; the accepted overlap length and correction burden must come from footage tests. If that repeatedly fails, prefer the separately assessed Cutie streaming comparator or a simpler restricted finishing profile.

## Finite-window mask contract review — 10 October 2026

This addendum is a source-only review of the already-acquired vendor package, not an inference, benchmark, Windows/CUDA qualification, or report of the parent's subsequently acquired runtime status. No model execution, dependency acquisition, media modification or application-code change was performed for this review. The earlier runtime sections remain dated research/provenance findings, not a fresh inventory of the private evaluation runtime.

**Upside:** the ordinary public SAM2 predictor can provide two-object, explicitly directed finite-window coverage without changing its internals. **Downside:** labels alone do not transport appearance identity between fresh states; copied mask anchors and empty overlap can make a seam check deceptively reassuring. **Verdict:** proceed with the bounded design, but modify seam acceptance to exclude conditioning/seed frames and distinguish confirmed absence from tracking loss. **Alternative:** when overlap lacks usable evidence, stop that mask range for correction or use a bounded previously approved visible anchor; do not introduce a new tracker/refiner dependency. **Next step:** exercise coverage, seam, absence, correction and memory gates below before evaluating horse/rider edge quality on authorised footage.

### Minimal application-owned interface — proposal

Expose one bounded primitive such as `generate_window_masks(request, cancellation) -> staged_manifest`. A whole-clip coordinator may call it, but must not exchange or persist opaque SAM2 inference dictionaries between windows. Keep the existing dependency set and ordinary `build_sam2_video_predictor` / `init_state` / `add_new_points_or_box` / `add_new_mask` / `propagate_in_video` public calls.

The versioned request should bind:

- A fixed model/runtime/profile identifier and verified hashes; no arbitrary model path, Python imports, Hydra overrides, shell fragments or remote model identifier supplied by a media sidecar.
- An application-created JPEG-folder manifest with exact global-frame mapping, `global_start`, `frame_count <= 64`, homogeneous proxy width/height and max edge <=1024, source/stabilised canvas dimensions, frame rate/time base and the stabilisation/proxy transform fingerprint. Validate numeric local filenames, count, dimensions and their manifest membership before initialisation; the vendor loader does not establish those invariants for us.
- A single explicit local reference `r`, exactly two fixed application IDs (`horse=1`, `rider=2`), and a half-open owned output range `[a,b)` inside the window. Freeze identities before tracking even though this vendor version permits later object additions.
- Approved anchor records keyed by **global frame + object ID**. Convert global frames to local indices only after range checks. Each record is one canonical complete point/box prompt or one binary mask, not ambiguous simultaneous prompt types. Record the coordinate space; reject non-finite/out-of-bounds points, invalid labels and malformed boxes. Require a shared approved visible reference for initial horse/rider acquisition, or an explicit per-object absence/reacquisition decision.
- Anchor revision, provenance (`manual`, `approved_detection`, `accepted_overlap`) and any parent mask-manifest/hash dependency. A generated carry anchor is not an independent manual observation. Cap anchor count or split the window while retaining every accepted correction; do not silently discard corrections to satisfy a memory cap.
- Declared seed/conditioning frame sets and **held-out seam-check frame sets**, cancellation/generation ID, approved scratch/output locations, disk budget and immutable quality-policy version.

Stage per-frame records containing global frame, each object ID, compressed mask reference/hash, mask dimensions and reconstruction transform, lineage and one of `candidate_visible`, `confirmed_absent`, `unresolved`, `rejected` or `accepted_for_preview`. Store reason codes and measured seam values separately from these states. None should be labelled a calibrated confidence probability. Final acceptance requires complete, non-duplicated coverage of the owned range and an atomic manifest promotion. A cancelled or failed generation must not replace the previously accepted manifest or be reported as completed.

Do not convert arbitrary floating masks into binary through the vendor's implicit bool conversion: require bool or validated 0/1 planes at the interface. A non-tensor value of 0.1 otherwise becomes true before resizing. Soft alpha/matting is a different representation and remains outside this primitive. The baseline fixed profile should keep `vos_optimized=False`, explicit zero hole filling and no object-exclusive output/memory constraints; optional cleanup is a separately identified and visually tested profile. Hole/component filtering can remove reins and leg gaps.

### Directional coverage and correction replay

Use independent directional tracking histories **sequentially**, not two full live states retained together. The parent's fresh-state-per-direction plan is valid; the public `reset_state` followed by complete anchor replay is a lower image-allocation alternative, because its retained image features do not contain tracking history. Do not mutate private dictionaries to approximate a reset. Use synchronous bounded-folder loading and explicit CPU video/state offload in the GPU profile, and release the window state before the next window.

For a window of `N` frames and local reference `r`:

| Pass | Public call parameters | Frames yielded | Owned reference |
| --- | --- | --- | --- |
| Forward | `start_frame_idx=r`, `max_frame_num_to_track=N-1-r`, `reverse=False` | `r ... N-1` | Yes, if `r` lies in the owned range |
| Reverse, only when `r > 0` | `start_frame_idx=r`, `max_frame_num_to_track=r`, `reverse=True` | `r ... 0` | No; reference is QC-only/ignored for ownership |

Replay both object IDs and every accepted in-window anchor **before** either pass, in a canonical order and with one complete prompt per object/frame. Always pass the start explicitly: relying on default start chooses the earliest conditioning frame, which may differ from the chosen shared reference. Validate every yielded frame and exactly two expected IDs before storing an owned output. Test `N=1,r=0`, `N=2,r=1`, and `N=64,r=27`: total owned coverage must be 1, 2 and 64 respectively, with no duplicate reference.

These two coverage passes are not, by themselves, a forward/reverse consistency test: they share only the supplied reference. Genuine consistency evidence requires independently generated predictions on additional held-out shared frames. For a later global initial reference, process earlier windows backwards and later windows forwards using accepted neighbouring visible overlap anchors; never initialise a whole-clip prefix just to reach the reference. No frames preceding the reference may be silently omitted or accepted as zero masks.

All pre-replayed correction frames are conditioning anchors. Selected conditioning mask memory can include later frames, so a correction can change predictions on either side inside the window; the tiny model's past-pointer option does **not** make all conditioning-mask influence causal. Recompute the declared affected window after a correction and invalidate generated descendants of altered carry anchors until an independently approved anchor or explicit correction boundary stops that dependency. Record this in the manifest so a user can see why neighbouring previews became stale. Avoid a circular chain in which two windows each claim the other supplied their validating anchor.

### Seam and absence rules — rejection evidence, not proof of quality

The proposed per-object visible-overlap `IoU < 0.6` rejection floor is a useful starting alarm, not a source-validated horse/rider threshold and not a guarantee that `IoU >= 0.6` is correct. Two predictions can agree on the same wrong horse, omit the same fine reins, or remain stable through an ID swap hidden by the combined silhouette. Do not accept based only on union IoU.

Here “held-out” means the checked frame was not itself supplied as a conditioning mask/prompt. Predictions can still share anchors and model biases, so this is not statistical independence or calibrated temporal confidence.

1. Re-anchor on one chosen accepted visible overlap frame per ID, or a declared small anchor set. Reserve other shared frames for checks. **If every overlap frame is re-seeded via `add_new_mask`, every overlap prediction is a conditioning-mask echo and the check is tautological.** Exclude all supplied mask anchors and manual conditioning frames from independent-agreement counts.
2. Compare each expected object on the same global frames, coordinate transform and mask resolution. Retain each pair's IoU, visible/empty state, seed status and worst result, not just an average. As an initial proposed long-clip gate, seek at least three non-seed visible comparisons per object distributed across the overlap; shorter/no-evidence cases require review or abstention. This minimum is an application policy to validate, not an official SAM2 recommendation.
3. Check cross-ID overlap dominance, unexpected horse/rider near-duplication, rapid area/bounding-box changes and boundary/component changes as reason flags. Do not apply a universal full-frame area cap: the close horse can legitimately fill this user's frame. Thin edges and gait need separate visual gates regardless of silhouette IoU.
4. Define both-empty overlap as **N/A: no appearance evidence**, not IoU=1. One-empty/one-visible is a discrepancy. Distinguish user-confirmed absence from predicted emptiness/tracking loss; otherwise a bad tracker can obtain a perfect empty seam score.
5. On a failed/unresolved seam, leave the next owned range invalid for finishing and surface the global frame/object/reason. Do not average or crossfade conflicting identity masks to hide a seam. Abstention disables the added finishing effect for that range; it must not replace or remove the original subject footage.

**Zero-mask answer:** `add_new_mask` accepts a two-dimensional all-zero binary plane. In this tiny configuration the mask-input shortcut treats its pixels as supplied output, uses dummy IoU=1, decides appearance with `any(mask > 0)`, and produces a no-object pointer for absence. That is valid syntax for a confirmed absence anchor, but not an appearance-preserving handoff or independent confidence measurement. Resizing/thresholding means even a supplied non-zero seed is not guaranteed pixel-identical at output; agreement with it is still conditioned rather than independent. [Pinned model mask-input branch](https://github.com/facebookresearch/sam2/blob/2b90b9f5ceec907a1c18123530e92e794ad901a4/sam2/modeling/sam2_base.py#L415-L465).

If either object has no usable visible evidence in the overlap, use a last-approved visible anchor only within the declared bounded look-back/window budget, or require confirmed absence followed by explicit reacquisition when it reappears. A fresh state seeded only with empty masks has not retained the old visual identity just because it receives IDs 1 and 2. If additional history cannot fit the budget, abstain and ask for another anchor; do not quietly expand to a whole clip. Corrected/reacquired IDs must retain their application meaning and new lineage.

### Compressed ownership and resource guards — proposal and arithmetic

Use existing NumPy/Python facilities to losslessly bit-pack two **separate** binary planes; derive the horse+rider union on read. Specify bit order, dimensions, valid-bit count/padding, object/global frame, profile and content hash in a bounded header/manifest. If using a compressed array/archive, prohibit object dtype/pickle, validate member names/counts and decompressed size before allocation, and reject path traversal or a mismatched dimension/frame hash. Do not persist neural tensors, object pointers or an ambiguous soft-alpha array as the public mask cache.

Choose and record whether the stored mask is at proxy or stabilised-base resolution; the vendor's returned “original video” resolution is the **proxy folder** resolution in this design. Explicitly resample to the bound stabilised canvas with a fixed declared method when consuming a proxy mask. That transform is part of cache identity, not an assumption. Thresholded logits are a binary selection contract; they are not refined hair/rein alpha, and smooth upsampling does not recover information absent from a 1024-edge proxy.

- Stock internal image allocation is `N * 3 * 1024 * 1024 * 4` bytes for float32 images. At 64 frames it is **768 MiB**, before model weights, features, anchors, outputs and temporary copies. Limiting external proxy max edge does not change this internal square allocation. [Pinned eager loader](https://github.com/facebookresearch/sam2/blob/2b90b9f5ceec907a1c18123530e92e794ad901a4/sam2/utils/misc.py#L267-L279).
- Two full-UHD float32 output planes would be 66,355,200 bytes (~63.3 MiB) for one frame. Two packed binary UHD planes are 2,073,600 bytes/frame, or 6.22 GB per minute at 50 fps **before compression**. These are representation arithmetic, not measured runtime/disk requirements; compression ratio must not be assumed. Proxy-resolution caches have a different, explicitly recorded budget.
- Bound pending writer frames to one or two, discard each temporary logits tensor after validated compression, release every directional state/window, and do not accumulate a whole-clip Python list. `num_maskmem=7` limits attention slots, not all stored output dictionaries or conditioning anchors. CPU offload changes location, not the need to bound retained state.
- Preflight scratch/output headroom on the selected approved drive; observe process working set, CUDA allocated/reserved peak, staged bytes, queue length, windows/frames completed and cancellation latency. Treat 64 frames as a candidate upper cap, not a demonstrated fit on an RTX2060 6 GB. CPU smoke on the Intel Arc development host does not qualify CUDA throughput, quality or driver compatibility.

### Concrete validation gates

Before acceptance, require: exact global-frame/ID coverage including reverse-before-reference and one-frame cases; malformed proxy-folder rejection; deterministic canonical correction replay within numerical tolerances; mask pack/unpack equality including non-byte-aligned dimensions and corruption rejection; one atomic owner per frame; cancellation leaves accepted artifacts untouched; all-seeded overlap cannot report independent seam success; both-empty seam cannot report confidence; predicted-empty/reappearance is unresolved until the declared identity rule succeeds; and no stale generated descendants survive a correction revision.

The subsequent authorised footage evaluation must cover close full-frame horses, crossing/occlusion, rider disappearance/reappearance, manoeuvring legs, mane and reins, thin gaps against bright bokeh, actual window boundaries and frames on both sides of each correction. Inspect fixed crop overlays at 100/200% and playback at source cadence. Verify foreground-only finishing leaves the outside-effect-mask stabilised base unchanged before lossy encoding. Measure peak resources across increasing clip duration and bounded state release, then test the actual RTX2060 driver/runtime separately; **no throughput extrapolation from an A100 or CPU smoke**. A seam-pass status alone must never be presented as a quality-pass status.

For example, paired acquisition at frame 3 plus a horse correction at frame 1 fails instead of participating in reverse propagation. Keep acquisition reference explicit or separately select the earliest shared horse/rider acquisition frame; do not conflate it with the earliest correction. ### Correction independence and directional edge assessment

The newly implemented checks correctly re-seed only the start frame per ID. All in-window manual anchors are applied before propagation; any anchor on a compared frame excludes that entire frame, conservatively excluding both IDs even if only one was corrected. The start seed is excluded, both-empty pairs are skipped, one-empty/one-visible gives IoU zero and fails, and each object needs at least one remaining visible comparison. Thus manually corrected/seeded frames cannot themselves produce the successful held-out check seen in the static nine-frame receipt. The policy may reject a short heavily corrected overlap, but this is fail-closed, not false independent confidence. Generated predictions still share anchors and model biases; “held-out” does not mean statistically independent or calibrated.

An empty carried start mask fails **before** replaying manual prompts. This deliberately prevents automatic re-identification, but also means adding a manual reacquisition anchor at that same handoff frame cannot resolve the error in the current implementation. Make that limitation explicit, or permit a separately identified, user-approved visible reacquisition event without claiming empty-mask continuity. Source: `subject_mask_job.py` lines 145–163.

Source arithmetic supports the expected edge ownership: ref0 skips the empty reverse-owned pass; a one-frame clip yields its reference once; a reference at the final frame gives one forward reference plus reverse-owned opening frames; and final short windows own their entire remaining range. Each propagation uses `len(window.frames)-1` with an explicit start and checks the complete expected frame set. This is a source assessment, not an executed edge-case test. Add public tests for every reference position on small counts, overlap=1 admission rejection, tail windows, earlier single-ID corrections and corrections consuming all overlap evidence. Sources: `subject_masks_contract.py` lines 25–53; `subject_mask_job.py` lines 169–175, 216–229.

### Alpha/fringe handling: safe conservative intent, unproven subject quality

The current cache is **one union finishing-alpha plane**, not the previously proposed two-object binary segmentation cache. Identity checks occur on separate binary masks in memory, but only `blur1(erode5(horse OR rider))`, clipped back inside the union, is persisted as 8-bit alpha. The Python RLE writer/readers correctly bound decoded geometry, record size, run inflation, count and EOF; no pickle/opaque neural state is serialised. This is a simple application-owned finishing artifact, provided its schema/profile is described accurately. Sources: `subject_mask_job.py` lines 197–205; `subject_mask_cache.py` lines 14–97.

The alpha clipping prevents Gaussian feathering from adding an effect outside the **predicted proxy union**. The native reader uses nearest-neighbour reconstruction; subject colour blends with that alpha, and sharpening additionally demands highly opaque local masks. This helps protect predicted background and avoids fractional-mask sharpening at the matte edge. It does not prove that the predicted union equals the actual horse/rider boundary. Sources: `mask_cache.h` lines 25–39; `core.h` lines 45–77, 158–177.

`MinFilter(5)` is a two-proxy-pixel erosion radius: at 3840->1024 scale that represents about 7.5 original pixels on each side, before the one-pixel Gaussian feather. Thin mane/reins/legs can disappear or receive little finishing effect; a nearest-upsampled coarse mask can also expose edge stair-stepping. Do not call this refined video matting or quality-proven horse finishing. Keep the erosion/feather/reconstruction profile in identity (now done), show raw-union versus applied-alpha overlays at 100/200%, and evaluate colour/fringe consistency plus normal 50-fps playback. Distinguish deliberately conservative edge exclusion from tracking failure and from actual background leakage. No new refiner dependency or blanket untested morphology change is recommended by this review.

### Agreed narrow implementation recommendations

The parent will implement the following; this reviewer has not changed or exercised that implementation:

- **Explicit shared acquisition reference:** add a versioned `referenceFrame` (or equivalent named field), validate both horse/rider acquisition prompts at that exact frame, and include it in the immutable recipe. Earlier/later single-ID corrections remain corrections and cannot silently move the acquisition reference. For any retained older selection format, derive only from a shared pair and record the chosen reference explicitly rather than taking the minimum of all anchors.
- **Coherent fixed window profile:** admit `4 <= windowFrames <= 64` and `2 <= overlapFrames < windowFrames` before decoding. An overlap with all its remaining frames conditioned still fails closed at runtime; two frames is a structural minimum, not a quality or confidence guarantee. Keep exact values bound in cache identity.
- **Truly lazy production planning:** compute one directional window and ownership range at a time, with fixed scalar cursor state. Do not build a clip-length list/tuple before first decode. Exercise all small-count/reference combinations through the same production planner and verify one owner per frame, including ref0, final reference and short tails.
- **Geometric profile admission:** require known square SAR and identity orientation; reject rotation tags/non-identity display matrices rather than silently relying on FFmpeg autorotation. Treat unknown metadata according to the fail-closed normalised-base policy, and retain the base's exact count/rate/content binding.
- **Time-varying decode provenance test:** use a tiny, visibly/frame-identifiably changing CFR source at 30 and 50 fps. Compare bounded-window decoded global-frame identities with a canonical full sequential decode for forward, reverse, reference-zero and tail cases, without involving SAM/model quality. This separates seeking/frame-map correctness from segmentation performance.

These close the central public-interface findings. Process-tree cancellation, path/executable/hash verification, transient disk/VRAM accounting and real horse/rider alpha quality remain separately named integration/acceptance gates; none is waived by a passing tiny synthetic mask run.
